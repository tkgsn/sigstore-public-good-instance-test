Rekor v2 Append & Verify

GitHub Actionsが仮SNP measurementを含む署名対象をRekor v2へappendし、検証者がデータの整合性・署名者・時刻・Merkle treeへの包含を確認する流れ。

TEST ONLY: 今回のmeasurementは実際のAMD SEV-SNP reportから取得した値ではありません。仮reportのSHA-384を使い、subjectにもplaceholder / test-onlyと明記しています。

1

仮measurementを作る

dummy-snp-report.txtのSHA-256とSHA-384を計算する。後者を仮measurementとして使う。

GITHUB ACTIONS
2

Subjectへ格納する

commit・run IDとともに、値をsnp.measurementへ格納し、test-onlyであることも署名対象に含める。

GITHUB ACTIONS
3

身元と鍵を結ぶ

GitHub OIDCをFulcioが確認し、一時公開鍵とworkflow identityを結ぶ短期証明書を発行する。

FULCIO
4

Hashを署名する

SNPフィールドを含むSubject全体のSHA-256をECDSA署名し、TSAからRFC 3161 timestampを取得する。

COSIGN + TSA
5

Entryを提出する

Subject本体ではなく、digest・signature・Fulcio certificateをhashedrekord 0.0.2として提出する。

COSIGN → REKOR V2
6

Merkle treeへappend

Entryを追記し、log index・audit path・root hash・signed checkpointをbundleへ返す。

REKOR V2

検証範囲: 仮reportとsigned subjectの値が一致することは検証しますが、AMD証明書・SNP report署名・TCB・nonceなどのattestation検証は行っていません。

1

Placeholder data

仮reportのSHA-256／SHA-384を再計算し、signed subjectの値とplaceholder表示を確認する。

2

Subject digest

subjectをSHA-256化し、bundleのmessageDigestと一致するか確認する。

3

Identity & signature

Fulcio chainとGitHub workflow identityを検証し、証明書の公開鍵でECDSA署名を確認する。

4

Trusted time

RFC 3161 tokenをTSA trust rootで検証し、署名がFulcio証明書の有効期間内に存在したことを確認する。

5

Inclusion proof

leaf hashと17個のaudit-path hashを合成し、checkpointに記載されたroot hashへ到達することを確認する。

6

Signed checkpoint

TUF TrustedRootのRekor Ed25519鍵でcheckpoint署名を検証し、root hashを信頼できる状態にする。

rekor-v2-test-subject.json

署名対象の元データ。Rekorには本体ではなく、このファイルのdigestが登録される。

rekor-v2-test.sigstore.json

署名・証明書・timestamp・Rekor entry・inclusion proof・checkpointをまとめた検証bundle。

mediaType: sigstore.bundle.v0.3

signing-config.json

Cosignが署名時に使ったサービス選択。v2 shardをTUF配布設定から選ぶ。
